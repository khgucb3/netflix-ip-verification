## 为什么普通代理IP总被Netflix拦下来

Netflix有一套针对IP的检测系统，核心判断只有一个：这个IP是不是真实用户的家庭宽带。机场、数据中心和云服务器批量产出的IP段，早就被标记成Datacenter类型，一进检测流程就会被拦。共享代理还有另一层问题——同一个IP段上挂着几百个账号同时在线，还可能留下大量代理流量记录和被举报的历史，这些都在Netflix的考察范围内。

原生IP指的是从注册那天起就归属当地ISP的IP，没被大量用户共享过，也没进过黑名单。在Netflix的数据库里，这类IP的身份是“正常用户”，所以能正常展示完整内容库。同样是挂代理，用住宅IP的人能看，用机房IP的人只能对着红屏，差别就在这里。

## 原生IP、广播IP、机房IP差在哪

一句话版本：Netflix看的是IP的“注册身份”和“实际位置”是否一致。

| IP类型 | Whois特征 | Netflix的反应 |
| --- | --- | --- |
| 原生IP | 注册机构是当地运营商，注册地与服务器实际位置一致 | 视为正常用户，大概率完整解锁 |
| 广播IP | 注册地在A国，服务器实际跑在B国 | 容易被识别为绕路，常提示代理错误 |
| 机房IP | ASN标注为Hosting / Datacenter | 基本直接拦截 |

广播IP（也叫anycast）是商家为了省成本，把自己持有的IP段广播宣告到其他地区——市面上VPS很多、原生IP很少，主要原因就在这里。判断方法不复杂：查whois，看Organization和Country两个字段，注册国家和服务器实际位置对得上，大概率就是原生。

## 拿到IP后，五步自己验证

1. **看Netflix内容库**：直接打开netflix.com，如果显示当地版本（比如日区能看到独家动漫），说明IP过了第一关。
2. **查IP类型**：在ipinfo.io输入IP，看Hosting字段——Yes是机房IP，No是住宅IP。
3. **查whois归属**：确认注册机构是当地宽带运营商，而不是某个托管商。
4. **测DNS泄漏**：在DNSLeakTest选Extended Test。如果DNS服务器位置和IP位置对不上，流媒体可能误判你的真实位置。
5. **进阶验证**：用curl带上代理请求一个Netflix剧集详情页，返回200状态码，就说明这个IP能正常访问对应区域的内容。

两个容易忽略的细节：测试时关掉浏览器的定位功能；设备的时区和语言设置尽量与IP所在地区保持一致，否则也可能触发风控。

## 常见问题

**挂了原生IP，Netflix还是提示代理错误？**
说明这个IP可能被前人用过或已被标记。先换一个同地区的IP再试；如果换完仍不行，检查设备时区和语言是否与IP位置一致。

**看视频中途卡顿怎么办？**
家宽和住宅线路在晚高峰有波动属于正常现象。切换到同地区的其他节点，或开启代理软件里的线路优化选项。

**解锁会突然失效吗？**
会。Netflix会定期更新IP黑名单，任何IP都有被标记的可能，区别只是概率。如果检测显示“仅解锁自制剧”而不是完整解锁，说明这个IP被标记过但没被完全拉黑，换个IP通常能解决。

**一台VPS能同时看几个区？**
IP在哪个区就只能解锁哪个区的内容。想同时看美区和日区，需要两个对应地区的IP。
